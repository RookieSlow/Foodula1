# Foodula1 简约赛车科技 UI

更新：2026-10-14。范围：现有 uGUI/TMP 界面视觉升级；用户已预先授权自主视觉选择与文件修改。本文补充 `ui-modernization.md`，对本任务新切片采用下述克制主题，不宣称旧屏幕已经迁移。

## 1. HUD 理念与玩家需要

玩家在回合输入时需要迅速辨认“已经发生什么、当前选择可能发生什么、下一步能做什么”。优先清晰数字、中文状态和稳定位置；美食赛车身份由现有车队名称、卡牌与六队控件保留。首包只处理 `RaceTelemetryStripUI`，共享 token 独立定义，避免一次改变所有旧界面。

方案比较：沿用 Kenney 蓝色粗框成本最低，但不符合减少装饰的目标；整屏重排信息层级充分，但同时影响牌区/赛道/教程定位；本轮选用原位置上的平面数据条，能保留心智模型与原输入路径，适合后续按屏迁移。选择依据是用户已明确的简约、清晰、有层次方向。

## 2. 信息架构

| 信息 | 可见性 | 来源 | 优先级 |
|---|---|---|---|
| 已移动 / 预计格数 | 原数据条常驻 | TurnMovementBreakdown / RaceTurnPreview | 1 |
| 实际 / 预计热量、容量、费用不足 | 常驻；预计仅输入有效时 | HeatGaugeState / preview | 1 |
| 挡位试算与所选模式 | 试算时替换原摘要 | TeamGearRules 原显示名称 | 1 |
| 卡牌/车手/科技/其他位移来源 | 原条形分段，文字按需 | 原 Entries | 2 |
| 具体费用、缺牌、冷却、回退及预测边界 | 原明细入口 | FormatDetails 原文案 | 3 |
| 排名/圈数/回合/状态/挡位 | 原 HUD 保留，下一包迁移 | HUDUI/现有展示规则 | 1 |
| 手牌、牌堆、技能、进站、车道选择 | 原控件保留，后续迁移 | 既有状态与事件 | 1/2 |
| 科技、奖励、车手成长、生涯进度 | 原菜单/结果按需 | 既有界面 | 3 |

细节通过已有点击入口渐进披露。颜色只辅助，摘要和明细必须保留“已/实际/预计/试算/费用不足”等语词，不将预计误作真实资源。

## 3. 布局与安全区

首包保留原 HUD 数据条 RectTransform、分辨率缩放、锚点与明细按钮；不扩大占用赛道区域。两个单元上下排列：上方位移摘要及细条，下方热量摘要及实际/预计双轨。摘要左侧内缩 4%、右侧内缩 2%，每条顶部使用 1 个参考像素细线。沿用原文字与轨道锚点，以不裁切中文为约束，并以真实截图记录。

1920×1080 和 2560×1440 是当前自由赛 GDD 明示验收尺寸。1280×720 作为额外较小窗口压力检查，不据此宣布新增最低支持规格。原屏幕边距不改；不得用整屏 overlay 遮盖布局问题。

## 4. 视觉 token 与资产清单

| token | sRGB | 用途 |
|---|---|---|
| Graphite | #101317 | 最深背景/轨道 |
| Surface | #171B20 | 数据条平面底 |
| Raised | #222830 | 轻微层级，不渐变 |
| Primary | #F4F6F8 | 摘要与数字 |
| Secondary | #B6C0CA | 单位、解释 |
| Separator | #46515E | 1 像素分隔，不承担状态 |
| Actual | #67C6E5 | 当前/实际轨道 |
| Projected | #F2C66D | 预计轨道 |
| Critical | #FF8178 | 不足/危险，必须有文字 |

颜色在深底上的文字目标对比度至少 4.5:1；实际结果由实现测试计算并记录，不把调色表当测量。原位移来源色可继续占用细条小面积，不能整块染底。取消粗 Outline、外发光与不必要渐变；新增元素无阴影动画。摘要保留当前中文字体与字号作为基线，允许按真实容器提高可读性，禁止替换为不完整西文字体或单纯缩小中文掩盖溢出。

新增资产清单：原创 uGUI Image 矩形/分隔线；不需要纹理、官方图形、图标包或新字体。既有资源许可见 [许可清单](../../docs/ui/racing-tech-resource-licenses.md)。

## 5. 状态与流程

正常输入 → 选择挡位/拖杆 → 原试算更新 → 选择/取消牌 → 原实时预计更新 → 原确认事件 → 权威实际结算。首包仅改变表现。

待出牌显示原提示；挡位试算明确使用“手牌试算”；实际移动始终按账本；预计热量只在 preview 有效时出现，上轨预计、下轨实际。输入关闭时撤销预计。费用不足显示原不足文案。失控/回退保留明细的单独说明，不能把回退算进正向长度。

中国保持 Go/Recover；英国 H 挡、德国拨片、意大利门式、美国推拉、日本快速换挡保留各自形态与事件。六队仅在数据条使用一致信息语法，不统一成相同挡位玩法。

## 6. 信息层级与视觉预算

数据条只保留两个主要摘要、两个轨道区域、每条顶部一条细线；新增装饰共两个矩形，不新增固定按钮/模态层。实际和预计同屏时必须在文字与位置两方面可区分。赛道中心区域无新增常驻内容。初始实现不引入新的全局 HUD 数量/不透明度设置。

## 7. 反馈与交互

沿用原明细按钮点击回调及按钮状态；装饰、轨道、文字 raycastTarget=false，不挡牌拖动或教程聚光。明细遮罩与关闭行为沿用现有模式；不增加声音、不增加每帧重建、不改变确认偏好。禁用/待选/锁定状态必须保留原文案或形态。无新增提示队列；已有状态栏优先级保持。

## 8. 平台与可访问性

目标为当前 PC 鼠标点击/拖动与既有键盘路径。原输入可达性需回归；本轮不添加游戏手柄、重映射、字幕或新色盲模式，也不宣称这些已支持。摘要、轨道空间分层和明细文字提供非颜色识别。无闪烁、无新动效；既有减少动态选项仍有效。字体 material/atlas 与字体资源不替换。

## 9. 可调参数

设计 token 与局部间距在主题代码集中维护；数据源、费用、挡位合法性、AI、存档、快速播放设置均不属于可调参数。不存在新增面向玩家的 UI 设置。

## 10. 验收与证据边界

实现、测试及截图在 [屏幕验收清单](racing-tech-ui-checklist.md) 跟踪。至少检查两规定尺寸及小窗口、六队、长中文/大数字、实际/预计/费用不足/输入关闭；检查裁切遮挡、点击、禁用、拖动与明细。真实 UI 受控夹具必须明确标识；不能当完整默认赛事通过。历史 185/185 与 56 图只提供旧行为上下文，不计本轮结果。

## 13. 第二包：HUD 外壳、排名与状态

日期：2026-10-14。用户已授权本任务自主选择视觉方案；本节为设计与实现约束，实际完成情况只以验收清单和本包测试/截图为准，首包历史通过数不挪作本包证据。

### 13.1 玩家需要与选择

玩家应沿原位置找到操作、当前赛事信息和牌桌，12 车时能查看完整排名。对比方案：全屏重排可能改善列宽但会改变熟悉的空间位置；仅改背景易实施但不解决长名单可达性；本包选择原布局平面化并保证名单滚动，不触及挡位/卡牌/按钮/弹窗外观。此选择采用稳定位置与渐进披露原则，降低迁移对现有操作心智模型的影响。

### 13.2 范围与数据契约

| 对象 | 本包允许 | 必须保留 |
|---|---|---|
| OperationPanel | 自身底色、顶部细线、已有标题颜色 | RectTransform、动作栈、按钮/挡位控件后代样式、监听器 |
| ScoreboardPanel | 自身底色、标题/只读状态文字层级、既有排名文字可滚动 | 原圈数/格数/排名/AI 状态完整字符串、TMP 引用、刷新绑定和顺序 |
| DeckTablePanel | 自身底色、已有区域标题颜色、顶部细线 | 手牌/牌堆/出牌区位置、选中牌与拖动反馈、所有按钮 |
| TrackFrame / 摄像机 | 不处理 | 透明背景、原 TrackViewport 与赛道视口完全保持 |

`RaceHudTextRules` 原样生成文字，`HUDUI.Refresh` 原样赋值。不得重写排名算法、删名缩名、删掉“完赛/退赛/维修”等状态，也不得把中文单位换成未解释图标。0/1/2/4/6/12 车使用同一个只读展示路径；0/1 只是健壮性夹具边界，不扩展自由赛规则。

### 13.3 视觉与布局

三个底板统一 Surface `#171B20`，允许排名区使用 Raised `#222830` 建立轻微层级。标题使用 Primary `#F4F6F8`、普通统计与辅助说明使用 Secondary `#B6C0CA`。各面板最多新增一条顶部 Separator `#46515E`，参考画布 1 像素；不描四面粗框，不加背景纹理、倾斜边、发光或渐变。仅停用这三块底板自身 Outline/有装饰的 Sprite，不递归去除按钮、挡位、卡牌或教程边框。

以现有字体与字号为起点；紧凑来自一致行距/边距和去装饰，不能靠整体缩字实现。排名保留原单一 TMP 内容，不为了仿官方多列而拆成新增数据绑定。标题、比赛状态、排名、资源统计保持原视觉顺序，白色主层级与灰色辅层级须在深底上实测至少 4.5:1。面板位置、尺寸、兄弟顺序及 TrackViewport 不变；不越过操作面板到赛道中间加常驻标题。

### 13.4 长名单与滚动

优先复用已存在的排名 ScrollRect/Viewport/Mask；不得重置用户原滚动位置来模拟刷新成功。若排名原来没有滚动容器，可在 ScoreboardPanel 内创建局部滚动适配器并把**原 TMP 对象**作为 content，保留 `hud.standingsText` 对象引用及文本绑定。本包保留 ScoreboardPanel 外锚点，内部排名 viewport 则明确调整为横向 `0.06–0.94`、纵向 `0.045–0.43`；这不是保持旧排名文本矩形，而是给统计区与可滚动名单划出独立区域。垂直 content 高度由 TMP preferredHeight 和 viewport 高度取较大值；横向禁止滚动，长名自然换行，保留每条原文。内容不足时无额外滚动范围，初次显示在顶部；普通刷新不抢回顶端，人数/内容变短时只作范围钳制。

12 车场景必须实际滚到末尾并看到第 12 行；截图仅看到前三行不能当完整名单验收。滚轮/拖动仍走 uGUI ScrollRect 原机制，不增加全局输入监听。装饰不接收射线；滚动命中区限制在上述排名 viewport，不吞掉操作按钮、牌区或赛道拖拽。若新增滚动条，放在此矩形内，保留可见拇指且不可仅靠颜色表达可滚动性，不改变其他面板位置。

### 13.5 状态、可访问性与预算

输入、移动、完赛、退赛、教程回看/聚光、生涯赛事仍使用原显示/隐藏及交互门控。本包无新通知、音效或动效，无新增可交互状态按钮，减少动态设置不受影响。保留原键盘路径；没有足够依据宣称新增手柄支持或整体可访问性等级通过。长名单依赖滚动而非极小字号，费用/实际/预计等首包语义保留。

视觉预算：三个现有底板、最多三条非交互细线；最多一个原排名区域内的滚动适配层，不增加全屏面板。应用样式应在布局建立/绑定时执行，不在 Update 每帧遍历、重建、加载资源或重绑事件。复用 authored 与 fallback 两条路径，不修改干净场景或用户手工锚点。

### 13.6 交付验证与设计审查

必须验证：原三个面板锚点/TrackViewport 不变；原文字与绑定逐项保留；已有挡位/牌区/按钮外观与回调不被递归覆盖；重复 Apply 不累积细线、ScrollRect 或监听器；空名单和缺失可选面板安全。真实截图至少 1920×1080、2560×1440，另作 1280×720 压力检查；至少包含 2/4/6/12 车、长中文及较大圈数/回合/状态字符串、六队身份和滚至末尾证据。受控生产预制体截图需明确标识，不当完整默认赛事验收。

UX 审查结论：**APPROVED（仅第二包有界实现）**，设计阻塞 0。数据来源、空间范围、名单可达性、输入命中、重复应用与证据门槛已明确。视觉审查结论：**APPROVED（按上述 token 与局部范围实施）**；不依赖未授权资产。实际视觉、交互、性能与模式验收待本轮运行，未因此提前通过。既有艺术/HUD 完整规范、可访问性等级文件和治理文件缺失仍只记录，不创建占位。

本包重新 search/open 官方排名页、Kenney 面板许可、Adobe 字体许可与 Google 图标许可。官方排名信息组织与此前实际看到的固定列/细分隔一致；本次浏览器工具不可用，未取得新的官方网页截图，不把再次解析网页称为重新看过转播。无需第三方图标或字体下载，继续原创 uGUI 几何并保留现有中文字体。

## 14. 第三包：侧边温度计与六队挡位内饰

日期：2026-10-14 开始，2026-10-15 恢复收尾。用户已授权本任务自主视觉选择；本节是有界设计门槛，不提前宣布截图、测试或整屏升级完成。

### 14.1 范围与选择

本包仅处理 `HeatThermometerUI`、实际入口 `TeamGearPresentationUI` 和其 `TeamGearGraphic`。选择在原几何/原位置上平面化，并提高标签对比度；没有选择整套通用旋钮替换或重排控件，因为六队实际操作方式与形态已经形成稳定心智模型。`RaceCarBadgeUI` 是世界空间独立切片，留待下一包；停用的旧 `GearDialPresentationUI` 不改，卡牌/主按钮/弹窗与已完成的数据条/排名外壳不扩域。

### 14.2 温度计信息契约

保留十段、真实 `HeatGaugeState`、原百分比取整、50%/70% 分级与原刷新时序。实际在左、预计在右，原“预”字及实际/预计数值必须保留；forecast 消失后预计列隐藏，不能残留旧值。不得用预计覆盖当前热量或写回资源，不调整热量容量、费用或冷却规则。

底与未激活段使用 Graphite/Surface/Raised；实际、预计和危险用共通主题语义色，搭配左右形态与文字。刻度仍按原位置、阈值和数量，不能因简化装饰删掉风险分界。取消持续 critical 明暗脉冲，危险用静态高对比颜色/数值表达，避免每帧为装饰更新；这一表现决定依据本任务减少动画授权，覆盖旧 visual-style 6.1 的持续闪烁描述，不改变危险等级规则。

### 14.3 六队交互与身份

| 车队 | 必须保留的几何/交互身份 |
|---|---|
| UK | 经典 H 挡路线与原挡位点击 |
| DE | 方向盘拨片及原升/降挡点击、当前数字 |
| IT | 金属开槽门式轮廓及原挡位点击 |
| US | 顺序推拉杆拖动、释放和右侧数字入口 |
| CN | Recover/Go 两模式和原模式/连用反馈 |
| JP | 快排轮廓与原升/降挡点击 |

所有按钮/拖杆 RectTransform、命中范围、可用门控、回调/确认偏好与键盘路径保持。`CurrentGear` 与 `PendingGear` 的原状态文案、锁定/禁用、试算与费用解释保持；颜色之外仍依靠原指针/槽位/状态文本表达实际和待选。不改变卡牌需求、净换挡范围、CN 连用或支付结算。

允许移除木纹重复条、螺丝、重复厚倒角和金属高光，仅保留识别所需 H 路线、开槽、拨片或杆体。共通底板使用石墨色，细边和局部队色保持六队身份，避免大面积彩底。标题/数字高对比白，说明次级灰；不得降低字体/字图质量来压缩容器，也不引入外部字体。

以标准 sRGB 线性亮度公式计算，以下均为不透明底；最终实现应测试实际配置和交互状态，不能只验静态调色表。
