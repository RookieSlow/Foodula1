## 运行时指引格式

每个 `TutorialStepDefinition` 维护章节、标题、五个内容字段，以及一个聚光目标和一条独立
区域说明。运行时不再把字段显示成说明书式标签，而按以下节奏组织：

1. 高光实时目标区域，并用 `focusIntroduction` 单独解释它负责什么。
2. 用一两句自然语气说明本步机制及其用途。
3. `现在场上`：需要时交代脚本已准备的位置、挡位、牌区、天气或阶段。
4. `轮到你了`：只给当前唯一需要的点击、出牌或等待动作。
5. `完成后`：需要时说明真实比赛事件触发后玩家会看到什么。
6. `没反应？`：仅在可能卡住或等待结算时提供短恢复提示。

正文构建器会完全省略留空的可选字段，不显示空标签和多余空行；顶部上一项反馈同样只在已配置
成功文案时出现。机制说明、唯一操作和聚光说明仍为必填项。

阅读确认步骤使用“开始第一回合 / 牌区已看懂 / 天气规则已看懂 / 重置并开始练习”；实际操作
步骤的按钮不可交互并显示“等待本步操作”。状态机保留最近完成步骤，下一步面板显示其成功
结果。维修区延迟执行和英式早餐茶特别标注跨回合等待，避免玩家在中间状态误以为流程停住。
需要全新回合状态的课程在真实事件满足后延迟到下一回合边界显示：第 3 步换挡课、第 5 步
牌区课与第 7 步冷却课均先让上一回合完整完成，再依次应用检查点、立即对准玩家镜头、准备
选挡 HUD，最后刷新面板和高光。第 4 步确认出牌后只高亮赛道并解释移动，不再指向已经离开
手牌区的牌；第 5 步显示前按正常确定性牌序提前执行本回合补牌，因此手牌、抽牌堆和弃牌堆
都处于可观察状态，随后正常抽牌阶段不会重复抽牌。
进入这次牌区展示前会自动跳过上一回合的可选弃牌输入，避免旧的第 4 步面板遮住弃牌确认并让
流程看似卡住；已经打出的两张速度牌仍由正常回合清理进入弃牌堆。

面板默认锚定右上安全区，宽度最多 540；基础高度按屏幕高度的 72% 缩放，长正文则依据 TMP
首选高度向下扩展，进度与三枚底部按钮随面板底边下移，最终不超过屏幕安全高度；
低于 460 宽或 380 高时切换紧凑字号。收起尺寸最多 420×104，只保留标题、章节进度和展开按钮。
收起/展开不调用 `TutorialRuntimeDirector.TryPerform`，因此不会绕过阅读确认或实际事件门控。

`TutorialFocusHighlightUI` 位于教程面板下层、比赛 HUD 上层。四块半透明遮罩只压暗目标外区域，
目标获得金色边框，短说明优先放在目标下方、空间不足时移到上方。全部 Graphic 关闭 raycast；
减少动态时边框不呼吸。13 类语义目标覆盖比赛状态、回合提示、挡位、手牌、牌区、引擎、结束
出牌按钮、赛道、天气、维修选择、司康、英式早餐茶和总结。维修选择未出现时先聚焦赛道，面板
激活后自动切换；两张 UK 卡按 `trickId` 解析实际手牌实例。每步高光在下一次独立鼠标单击后
关闭，并记录本步已关闭状态，防止状态刷新时重新出现；进入下一步时重新显示对应区域。

### Prefab 手工编辑

可视化权威位于 `Assets/Resources/Prefabs/UI/TutorialOverlay.prefab`。将它拖到比赛场景的
`RaceCanvas` 下即可在 Hierarchy 中就地调整；不要放在 Canvas 外。根节点的
`TutorialOverlayAuthoring > Steps` 对应 16 个步骤，可修改章节、标题、正文、聚光独立说明和按钮
文案，但步骤 ID 与真实动作门控仍由代码定义，不应在表现层重排。`TutorialGuidePanel` 下的标题、
正文、进度和按钮 RectTransform 可直接移动；`TutorialFocusHighlight` 上的参数控制聚光窗口留白、
边框厚度、说明偏移/尺寸和压暗强度。运行时先复用 Canvas 内的实例，没有时才从 Resources 自动
生成，因此手工拖入不会产生第二套教程 UI。收起只暂存紧凑布局，重新展开恢复 Prefab 人工布局。
为便于在 Prefab Mode 同时校正文案和位置，根组件还提供 `Preview Step` 选择项及组件菜单中的
“预览所选教程步骤 / 预览自由练习 / 预览练习完成”；预览只刷新当前可见 TMP 文本与按钮标签，
不创建运行时 Director，不触发检查点，也不写教程完成状态。“校验教程文案配置”会列出重复/缺失
ID、空白必填字段和断开的 Guide/Focus 引用；场上状态、成功反馈和恢复提示允许按需留空，且不
自动修复或覆盖手工内容。专用 Inspector 将上述入口
显示为常驻按钮和内联校验结果；预览操作支持 Unity Undo，方便继续手工调整。

## 玩家状态检查点

| 步骤 | 固定状态与恢复目标 |
|---|---|
| HeatPayment | 24 格、G1、普通起手 7、引擎 6；跨到 G3 必定可支付 |
| HeatCardsAndCooling | 30 格、G1、6 普通牌 + 1 手牌热量；低挡必定可冷却 |
| MissingCardPenalty | 34 格、G2、仅 1 速度牌 + 5 手牌热量、引擎 1；恰好支付一次缺牌 |
| CornerLimitAndSpin | 8 格、G2、前两张 3+2、6 热量在弃牌区；G2 冷回 1 后仍确定性打转 |
| Weather | 36 格、G1、完整安全牌区；清除打转与跳回合，确保雨天观察后可继续 |
| PitSelection | 130 格、G2、前两张 1+1；进入 132 虚拟入口前的预约窗口 |
| UkScone | 16 格、司康在手、引擎可支付 |
| UkEnglishBreakfastTea | 20 格、红茶 + 1 手牌热量，保证实际冷却目标存在 |

检查点只在挡位输入门或下一回合边界应用，绝不在移动、反应或弯道协程中途覆盖状态。
应用后先同步赛车 Transform、车道视觉、玩家镜头、手牌与 HUD，再刷新教程面板；不能等到玩家
再次确认挡位才显示新位置。RaceTestLog 记录步骤、位置、挡位、手牌、抽牌/弃牌数量、引擎热量
以及视觉同步标记。

尾流领航车是教程专用确定性参与者。它只提供位置与计划输入，不替换或改写
`RaceSession` 的正常尾流解析。

当前 `TutorialRuntimeDirector` 在步骤进入时发出一次性 cue。天气立即进入现有
`RaceSession.Weather`；Slipstream cue 先排队，在所有车辆完成基础移动后、正常尾流解析前
执行 `leader=42/player=40`，随后仍由 `RaceSession.ComputeSlipstreamChain` 判定。完整引导
Play Mode 尚未走到该步骤，因此代码接线与纯层测试不能冒充最终画面验收。

## 运行时接入清单

MainMenu 中保留的 `TutorialOverlay` Prefab 实例仅用于作者排版；`MainMenuUI.Awake` 会在首帧
渲染前隐藏它。运行时第一步必须在 Race 场景、玩家摄像机和选挡 HUD 均就绪后显示。

1. [x] 主菜单设置教程启动请求，不覆盖快速比赛选择。
2. [x] Race 初始化检测教程请求，构造隔离会话和精确牌组，不读取持久化科技/车手增益，
   并关闭非教学所需的车型被动数值与正常 RP/XP 结算。
3. [x] UI 将阅读确认、实际回合/卡牌/热量/弯道/尾流/维修区/UK 特殊牌结果映射为
   状态机动作；成功后才推进步骤和一次性检查点。
4. [x] 引导结束或主动跳过后销毁当前比赛状态，以 `Practice` 相位重建完整会话；圈数、
   车辆、精确牌组、热量、教学对手和阴天全部回到固定起点，不修改正式赛道圈数。
5. [x] 完成、重启、重播引导和退出均写教程日志；玩家完成一圈后立即结束，任何路径
   都不调用正常 RP/XP/解锁或进度结算。

练习面板主按钮在进行中为“重新开始”、完成后为“再练一圈”；辅助按钮重播引导，
退出按钮统一经 `SceneLoader.LoadMainMenu` 清理教程会话。现有 Reset 按钮也按当前教程
相位重启引导或练习。渐进式/响应式指引、高光目标、检查点与虚拟维修区定向 EditMode 为
`31/31`、全量为 `514/514`；2026-08-28 的早前受控 Play Mode 冒烟仍停在域切换状态，已安全
停止且未重试，因此完整引导、高光像素边界和面板遮挡仍是人工 Play Mode 最终验收项。
