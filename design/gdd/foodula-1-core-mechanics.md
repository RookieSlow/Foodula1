## 1. 核心游戏机制（HEAT 规则详细移植）

> 本章节详细描述所有需要实现的游戏逻辑，程序员可据此独立开发。

---

### 1.1 卡牌体系

游戏使用卡牌来驱动所有动作。每张卡牌是一个独立的数据对象。

#### 1.1.1 卡牌类型

| 卡牌类型 | 数值 | 来源 | 在手中的行为 | 特殊规则 |
|---|---|---|---|---|
| **速度牌（Speed）** | 1 / 2 / 3 / 4 | 初始牌组 | 打出 = 移动对应格数 | 必须打出（不能主动弃置） |
| **热量牌（Heat）** | 0 | 超速 / 推极限 / 技能 | 占据手牌位，打出 = 0 移动 | 可在冷却阶段移除 |
| **压力牌（Stress）** | 随机 1~4（打出时揭示） | 特定条件获得 | 打出时随机决定数值 | 引入不确定性 |
| **升级牌（Upgrade）** | 0~3（依牌而定） | 锦标赛间获取 / 技能树解锁 | 特殊效果 + 可能带移动 | 稀有，改变策略空间 |

#### 1.1.2 牌组构成

每位玩家拥有独立的牌组（Deck）、手牌（Hand）和弃牌堆（Discard Pile）。

**初始牌组（开局自动配置）：**

| 卡牌 | 数量 | 总计 |
|---|---|---|
| 速度牌 "1" | 3 张 | |
| 速度牌 "2" | 5 张 | |
| 速度牌 "3" | 3 张 | |
| 速度牌 "4" | 1 张 | |
| **速度牌小计** | | **12 张** |
| 热量牌 "0" | 3 张 | |
| **初始牌组合计** | | **15 张** |

#### 1.1.3 手牌管理规则

| 规则项 | 数值 | 说明 |
|---|---|---|
| 手牌上限 | 7 张 | 每回合结束时补至 7 张 |
| 回合开始自动抽牌 | 补至手牌上限 | 若牌组不足则洗入弃牌堆后继续抽 |
| 牌组抽空时 | 将弃牌堆洗牌 → 形成新牌组 | 但热量牌不进入弃牌堆（见 1.6） |
| 手牌溢出 | N/A | 不会发生，因为出牌数 ≥ 档位值 |

### 1.2 档位系统

档位是玩家每回合的"行动力"，决定了必须打出几张速度牌。

#### 1.2.1 档位规则

| 档位 | 每回合出牌数 | 说明 |
|---|---|---|
| 1 档 | 1 张 | 保守巡航，方便冷却热量 |
| 2 档 | 2 张 | 常规节奏 |
| 3 档 | 3 张 | 激进推进，热量积累快 |
| 4 档 | 4 张 | 极限冲刺，高风险高回报 |

**换档规则：**
- **升档**：每回合只能升 **1 档**（1→2→3→4）
- **降档**：每回合可以降 **任意多档**（4→1 一次到位）
- **保持**：可以不换档，档位不变
- **降档冷却**：每降 1 档，从**手牌**中移除 **1 张热量牌** 放回热量供应区
- **激进降档惩罚**：一次降 **3 档或以上**时，额外产生 `(降档数 - 2)` 张热量牌加入弃牌堆——模拟"急刹对引擎的冲击"

| 降档操作 | 冷却 | 额外产热 | 净效果 |
|---|---|---|---|
| 4→3（降 1 档） | 1 | 0 | **净 +1 冷却** |
| 4→2（降 2 档） | 2 | 0 | **净 +2 冷却** |
| 4→1（降 3 档） | 3 | 1 | **净 +2 冷却** ← 急刹！ |
| 3→1（降 2 档） | 2 | 0 | **净 +2 冷却** |

> **设计意图**：4→1 仍能净赚冷却，但不如分两回合 4→2→1 划算。惩罚的不是刹车本身，而是**太晚刹车**。

#### 1.2.2 无法出牌的处理

若玩家选了某档位，但手中速度牌数量不足（即手中混入了太多热量/压力牌占位，导致实际可用的速度牌不够），则：

1. 尽可能打出所有能打的速度牌
2. 不足的部分，每缺 1 张视为 **引擎故障**，产生 1 张热量牌加入弃牌堆
3. 本回合仍按实际打出的牌移动

### 1.3 完整回合流程

每个玩家的回合严格按以下 **7 个步骤** 顺序执行。数字版中，所有玩家先完成步骤 1~3（选档 + 出牌），然后再统一执行步骤 4~7（移动 + 结算）。

#### 回合流程图

```
┌─────────────────────────────────────────────┐
│  PHASE A：所有玩家同步决策（输入阶段）         │
│                                               │
│  Step 1 — 换档                                │
│  ├─ 选择新档位（升 1 / 不变 / 降任意）           │
│  └─ 若降档 → 执行冷却（移除热量牌）               │
│                                               │
│  Step 2 — 抽牌                                │
│  └─ 从牌组抽至手牌上限 (7 张)                    │
│                                               │
│  Step 3 — 出牌                                │
│  ├─ 打出 N 张速度牌（N = 当前档位）               │
│  └─ 所有玩家出牌完毕后进入结算阶段                │
├─────────────────────────────────────────────┤
│  PHASE B：按位置顺序依次结算（执行阶段）          │
│                                               │
│  Step 4 — 移动                                │
│  ├─ 总移动力 = 打出的速度牌数值之和               │
│  ├─ 每移动 1 格检查是否触发弯道判定               │
│  └─ 暂时标记最终位置（待尾流修正）                 │
│                                               │
│  Step 5 — 弯道判定                             │
│  ├─ 检查本回合移动路径上经过的所有弯道             │
│  ├─ 每个弯道：总移动力 vs 弯道限速                │
│  ├─ 超速部分 → 支付等量热量牌（放入弃牌堆）         │
│  └─ 支付不起 → 打转（见 1.8）                    │
│                                               │
│  Step 6 — 尾流判定                             │
│  ├─ 检查是否紧跟前车（距离 ≤ 1 格）               │
│  └─ 满足 → 额外 +2 移动（可再触发一次尾流判断）    │
│                                               │
│  Step 7 — 收尾                                 │
│  ├─ 将本回合打出的速度牌放入弃牌堆                 │
│  ├─ 更新玩家位置                                 │
│  └─ 传递回合给下一个玩家                          │
└─────────────────────────────────────────────┘
```

### 1.4 移动与位置系统

#### 1.4.1 赛道数据模型

赛道由一系列连续的 **格子（Cell）** 组成，形成一条首尾相连的闭环。每个格子包含：

```json
{
  "trackId": "monza_01",
  "cells": [
    {
      "index": 0,
      "type": "start_finish",      // 起点/终点线
      "cornerLevel": null,
      "cornerSpeedLimit": null,
      "weatherEffect": null
    },
    {
      "index": 1,
      "type": "straight",
      "cornerLevel": null,
      "cornerSpeedLimit": null,
      "weatherEffect": null
    },
    {
      "index": 12,
      "type": "corner_entry",
      "cornerLevel": 2,
      "cornerSpeedLimit": 3,
      "cornerLength": 4,            // 弯道占 4 格
      "weatherEffect": null
    }
    // ... 更多
  ]
}
```

#### 1.4.2 弯道数据定义

| 弯道等级 | 限速值 | 典型弯道类型 | 视觉参考 |
|---|---|---|---|
| Lv 1（缓弯） | 4 | 高速弯、大弧度 | 银石 Copse |
| Lv 2（中弯） | 3 | 发卡弯前的中速弯 | 蒙扎 Parabolica |
| Lv 3（急弯） | 2 | 发卡弯、直角弯 | 摩纳哥 Grand Hotel |

弯道占据多个连续格子。玩家在弯道区间的**任意一个格子**上结束移动时，都需要检视本回合的总移动力是否超速。

#### 1.4.3 位置排序规则

同一格内可以有多辆车。当两辆车在同一格时，按以下优先级排序：
1. **本回合移动力更大** 的车排在前面
2. 若移动力相同，**先到达该格**（先结算）的车排在前面
3. 尾流判断只对"紧跟前车"（距离 ≤ 1 格）生效

---

### 1.5 弯道机制详解

这是游戏最核心的风险/回报节点。

#### 1.5.1 弯道判定规则

对于玩家本回合穿过（或停在）的**每一个弯道**：

1. 取本回合 **打出的速度牌数值总和** = `totalSpeed`
2. 取该弯道的限速值 = `cornerLimit`
3. 若 `totalSpeed ≤ cornerLimit` → 安全通过，无惩罚
4. 若 `totalSpeed > cornerLimit`：
   - `超速值 = totalSpeed - cornerLimit`
   - 玩家必须支付 `超速值` 张热量牌
   - 每支付 1 张热量牌 → 从手牌中选 1 张热量牌 → 放回公共热量供应区

#### 1.5.2 支付不起的后果

若手中热量牌不足，支付所有能支付的热量牌后，剩余未支付的超速值触发 **打转**（见 1.8）。

#### 1.5.3 多弯道场景

若一次移动穿过了 **多个弯道**，每个弯道独立判定。例如：

> 玩家速度 = 5，穿过弯道 A（限速 3）和弯道 B（限速 2）  
> 弯道 A：超速 2 → 需支付 2 热量  
> 弯道 B：超速 3 → 需支付 3 热量  
> 总计需支付 5 热量

#### 1.5.4 车队操控属性对弯道的影响

赛车属性 **操控（Handling）** 的数值直接加成弯道限速：

```
有效限速 = 弯道原始限速 + 赛车操控加成
```

例如：意大利赛车操控 +2，在限速 3 的弯道中有效限速 = 5，以速度 5 通过不产生热量。

### 1.6 热量系统

热量是游戏的核心资源/惩罚机制。

#### 1.6.1 热量牌的生命周期

```
热量供应区（公共池）
    │
    │  超速 / 推极限 / 技能效果
    ↓
手牌（占据位置，可被打出 = 移动 0）
    │
    │  被打出时
    ↓
弃牌堆
    │
    │  牌组抽空洗牌时 → 混入新牌组
    ↓
手牌（循环）
    │
    │  冷却（降档时）
    ↓
热量供应区（公共池）← 回到起点
```

#### 1.6.2 热量产生途径

| 途径 | 产生量 | 去向 |
|---|---|---|
| 弯道超速 | 每超 1 点 = 手中 1 张热量牌 → 弃牌堆 | 弃牌堆 |
| 推极限（Boost）* | 主动宣告 +1~2 热量 → 本回合速度 +1 | 弃牌堆 |
| 引擎故障（手中速度牌不足） | 每缺 1 张 = +1 热量 | 弃牌堆 |
| 技能/天气效果 | 依具体效果而定 | 弃牌堆 |

> \* 推极限（Boost）为可选高级规则，Phase 1 原型阶段可暂不实现。

#### 1.6.3 冷却途径

| 途径 | 移除量 | 来源 | 去向 |
|---|---|---|---|
| 降档冷却 | 每降 1 档移除 1 张 | **仅手牌** | → 热量供应区 |
| 赛车属性"冷却效率"加成 | 降档时额外移除 N 张 | **仅手牌** | → 热量供应区 |
| 中国减速档 | 固定冷却 2 张 | **仅手牌** | → 热量供应区 |
| 赛道维修区（可选） | 进站移除全部 | 手牌 + 弃牌堆 + 牌组 | → 热量供应区 |
| 技能效果 | 依技能而定 | | |

> **设计说明**：冷却仅作用于手牌——"冷却的是引擎当前温度，而不是排气管里的旧热气"。弃牌堆中的热量牌只能等待牌组循环时自然回归，形成延迟惩罚。

#### 1.6.4 过热机制

| 热量占比 | 效果 |
|---|---|
| 热量牌 ≥ 手牌的 50% | 屏幕边缘出现"过热警告"视觉效果 |
| 热量牌 ≥ 手牌的 70% | 每回合自动弃掉 1 张随机速度牌（烹饪过度！） |
| 手牌全部为热量牌 | 无法出牌 → 自动打转 |

### 1.7 尾流机制（Slipstream）

#### 1.7.1 触发条件

步骤 6 执行尾流判定：

1. 玩家移动结束后，检查与**正前方最近一辆车**的距离
2. 若距离 **≤ 1 格**（即紧贴前车后方或同一格排在后面），触发尾流
3. 额外获得 **+2 移动**（基础值，可被赛车属性/技能修正）

#### 1.7.2 链式尾流

尾流 +2 可能让你追上更前面的车，再次触发尾流判定。**每回合最多触发 2 次尾流**，防止无限链。

#### 1.7.3 不能尾流的情况

- 前方是队友且本队选择了"不尾流队友"的策略（策略选项待定）
- 前方无车（你是第一名）
- 前车距离 > 1 格

#### 1.7.4 车队尾流效率加成

赛车属性 **尾流效率（Slipstream）** 直接加成尾流移动距离：

```
尾流移动 = 基础值 2 + 赛车尾流效率加成
```

### 1.8 打转机制（Spin Out）

#### 1.8.1 触发条件

满足以下任一条件时发生打转：
1. 弯道超速且手中热量牌不足以支付超速值
2. 手牌全部为热量牌，无法打出任何速度牌
3. 特定技能/天气效果触发

#### 1.8.2 打转处理流程

打转发生后依次执行以下 5 步：

1. **位置回退**：退回到触发打转的弯道入口前一格
2. **热量惩罚**：额外产生 1 张热量牌加入手牌
3. **强制降档**：降至 1 档
4. **跳过回合**：失去下一回合的全部行动
5. **收尾**：本回合打出的牌正常放入弃牌堆

#### 1.8.3 打转后的恢复

被跳过的回合中，玩家：
- 不能换档
- 不抽牌
- 不出牌
- 不移动
- 但仍可享受冷却效果（降档冷却依然有效，因为打转已自动降至 1 档）

### 1.9 赛道与圈数

#### 1.9.1 圈数规则

| 参数 | 建议值 | 说明 |
|---|---|---|
| 标准比赛圈数 | 2~3 圈 | 短赛道 3 圈，长赛道 2 圈 |
| 单圈长度 | 40~80 格 | 取决于赛道设计 |
| 通过起点线 | 圈数 +1 | 自动记录，UI 显示 "Lap 2/3" |

#### 1.9.2 通过起点/终点线

- 格子 `index: 0` 标记为 `type: "start_finish"`
- 当玩家从最后一格移动到第 0 格（完成一圈），或从第 0 格前方经过第 0 格时，圈数 +1
- 最后一圈通过终点线 → 比赛结束，记录名次

---

### 1.10 比赛结束与排名

#### 1.10.1 结束条件

1. **有人冲线**：任意玩家完成最后一圈通过终点线 → 该玩家锁定第 1 名
2. **其余玩家**：当前回合继续进行，直到所有非打转玩家完成当前回合
3. **排名规则**：先按圈数排序，同圈按位置排序，同位置按本回合速度排序

#### 1.10.2 锦标赛积分

| 名次 | 1st | 2nd | 3rd | 4th | 5th | 6th |
|---|---|---|---|---|---|---|
| 积分 | 9 | 6 | 4 | 3 | 2 | 1 |

### 1.11 数字版特有的自动化处理

以下逻辑在桌游中由玩家手动管理，数字版需自动处理：

| 桌游操作 | 数字版自动处理 |
|---|---|
| 手动洗牌 | 自动洗牌（Fisher-Yates） |
| 记住弯道限速 | 赛道界面直观显示，过弯时自动计算 |
| 记住热量牌位置 | 系统追踪每张热量牌的位置 |
| 尾流距离测量 | 自动检测并高亮可尾流的前车 |
| 多人等待 | 计时器 + 异步回合提交 |
| 违规操作防止 | 后端校验：升档 ≤ 1、出牌数 = 档位、热量支付无误 |
