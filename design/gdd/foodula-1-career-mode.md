# Foodula1 生涯模式系统设计

> 状态：In Progress
> 最后更新：2026-08-31
> 实现入口：`Assets/Scripts/Career/CareerModeRules.cs`

## 目标与边界

生涯模式把现有单场比赛串成一轮固定八站锦标赛。玩家开档时任选一支可用车队，确认后本轮不可更换；每站按最终名次积分，第八站后以累计积分产生总排名。生涯只复用正式比赛规则和八张正式赛道，不新增转会、合同、剧情或额外经济系统。

正常单场入口的玩家可见名称改为“自由赛事”。自由赛事继续保留自由选择车队、赛道、科技配置及当前随机牌组行为；教程仍保留 UK、勒芒、零增益、精确牌序和零正常奖励隔离。本模式不得修改这两条路径的选择状态或存档。

## 生涯状态机

| 阶段 | 进入条件 | 允许操作 | 离开条件 |
|---|---|---|---|
| `NotStarted` | 无有效生涯 | 选择参赛车队并确认新赛季 | 确认后进入 `Racing` |
| `Racing` | 存在锁定车队且有下一站 | 查看积分榜、开始规则指定的下一站 | 第 4 站结算进入 `SummerBreak`；第 8 站结算进入 `Completed` |
| `SummerBreak` | 已完成 4 站且尚未使用夏休调整 | 调整并确认本轮唯一一次科技树配置 | 确认后进入第 5 站前的 `Racing` |
| `Completed` | 已结算全部 8 站 | 查看最终总排名、新建或退出 | 明确新建后产生全新状态 |

所有门控必须由生涯规则层判定。UI 隐藏按钮不是车队锁定、赛道推进或科技树锁定的权威来源。

## 固定八站赛历

生涯直接复用 `TrackSelectionState.AvailableTracks` 的显式目录顺序，避免维护第二份赛道 ID 清单，也不依赖 Resources 枚举或字典顺序：

1. 银石：`silverstone_afternoon_tea`
2. 纽博格林大奖赛道：`nurburgring_bier`
3. 蒙扎：`monza_pasta`
4. 印第安纳波利斯：`indianapolis_burger`
5. 上海：`shanghai_dim_sum`
6. 铃鹿：`suzuka_sushi`
7. 纽博格林北环：`nurburgring_24h_endurance`
8. 勒芒旧慕尚：`le_mans_old_mulsanne`

目录必须恰好包含八个非空、互不重复的正式 ID。`fallback_42` 与教程虚拟维修区不进入生涯赛历。

## 参赛阵容与车队锁定

- 当前比赛配置最多为玩家加 3 名 AI，因此首个生涯版本采用四车阵容。
- 玩家可从 `UK/DE/IT/US/CN/JP` 任一车队开档；四车阵容必须包含玩家且不得出现重复车队。
- 确认开档后，`LockedTeam` 直到完成或明确放弃本轮前不可改变。
- 后续 Race 接入必须从生涯状态注入玩家车队；不得重新读取自由赛事的临时选择覆盖它。
- AI 阵容生成与跨存档保持将在状态服务切片确定；规则层已经接受并验证一个稳定、无重复的四车阵容。

## 积分与排名

首个四车版本使用集中可调的积分表：

| 名次 | 积分 |
|---|---:|
| 1 | 10 |
| 2 | 6 |
| 3 | 4 |
| 4 | 2 |
| DNF / 无效名次 | 0 |

单站正常完赛车辆的名次必须为 `1..参赛车数` 且互不重复；多个 DNF 可以同时存在并统一记 0 分。每站结果带唯一 `ResultId`，相同赛果回调不可重复推进或重复计分。

总排名依次比较：累计积分、胜场数、领奖台数、赛季最佳单站名次、最近一站名次，仍相同时按开档阵容的稳定顺序。该规则保证保存/读取后排序一致。正式平衡验收可调整积分常量，但不得把积分公式散落到 UI 或比赛管理器。

## 夏休科技树

- 赛季开始时记录一份明确的初始科技配置快照。
- 第 1–4 站期间科技树锁定。
- 第 4 站结算后进入唯一一次 `SummerBreak`；玩家确认调整前不能开始第 5 站。
- 确认后消费本轮夏休机会，并将新快照用于第 5–8 站。
- 第 5–8 站期间再次锁定；第 8 站结束后不开放无意义的第二次调整。
- 生涯科技快照不得直接改写自由赛事的长期科技档案。具体 DTO 和映射由持久化切片实现。

## 保存与恢复要求

持久化使用独立键 `Foodula1.Career.V1`，保存 schema/version、锁定车队、稳定四车阵容、完整八站 ID 与赛历版本、下一站索引、逐站唯一结果、积分榜校验快照、夏休是否已消费、初始/夏休后科技快照和完成状态。科技快照只保存 RP、已解锁/已激活节点和 UK 复制目标，不保存单场比赛的一次性触发状态。

加载不会信任保存的积分或阶段：`CareerSaveCodec` 先验证 envelope 和赛历，再从第一站起通过正常规则重放全部赛果，在第 4 站按保存的夏休快照恢复，最后逐字段核对阶段、下一站和积分榜。运行时仓储还会用当前 `TechTreeDatabase` 拒绝不存在或属于其他车队的科技节点。版本漂移、赛历变化、积分篡改、重复赛果或非法科技节点集合均返回 `Invalid` 安全空状态；原始无效值保留到玩家明确确认覆盖或放弃，不会静默删除。

赛后写入必须是幂等推进：`CareerModeService` 先克隆并重建当前有效状态，只在候选状态通过规则且仓储成功保存后替换运行态；保存失败时当前进度与已有存储 token 都不前进。继续生涯、新建生涯、放弃当前生涯必须有清晰 UI；覆盖有效或损坏的已有生涯，以及放弃当前生涯，都要求显式确认。

## UI 流程

1. 主菜单把原“开始游戏”显示名改为“自由赛事”，行为不变。
2. 新增“生涯模式”。无有效进度时进入车队选择与确认；有有效进度时提供“继续生涯”和经确认的“新建/放弃”。
3. 生涯总览显示锁定车队、当前站、八站进度、逐站结果、积分榜、玩家总分和总排名。
4. `Racing` 只允许启动规则层给出的下一站；`SummerBreak` 只允许打开生涯科技调整；`Completed` 显示最终排名。

- [x] B：版本化 DTO、隔离存储、规则重建验证、继续/放弃/新建确认、原子推进和两阶段科技快照。
- [x] C：主菜单“自由赛事”改名、生涯入口、车队确认、生涯总览与积分榜。夏休科技编辑仍明确禁用，比赛启动由阶段 D 接通。
- [x] D：以只读会话请求把指定赛道、锁定车队、稳定 AI 阵容和生涯科技快照注入 Race；教程优先级高于生涯、生涯高于自由赛事。赛后从实际加载赛道和四车运行态映射完赛/DNF，重新加载权威存档并原子写入，拒绝回退赛道、陈旧回调和保存失败；生涯不写普通 RP/车手 XP。
- [x] E：第 4 站结算后打开锁定车队专属的夏休科技草稿；解锁、激活与 RP 只修改生涯副本，取消不保存，明确确认后才原子写入夏休快照并开放第 5 站。普通 `TechTreeProfileStore` 不参与此流程。
- [x] F：第 8 站结果显示最终总冠军、玩家总分与最终排名；完成页提供受覆盖确认保护的“开启新一轮生涯”入口。每站结算写入结构化 `[CAREER_RESULT]` 成功/拒绝日志，包含站次、赛道、阶段、积分、排名和冠军。
- [ ] G：安全 Play Mode 端到端验收和视觉交互收口。

## 验收标准

- 六支车队均可开档，确认后 UI 与直接规则调用都不能换队。
- 只按上述八站顺序推进；错误赛道、重复结果和非法阵容均不改变状态。
- 每个有效名次、DNF、累计积分和稳定同分排序均有自动化回归。
- 第 1–3 站不可调科技；第 4 站后只开放一次；确认后第 5–8 站锁定；完成后不再开放。
- 第八站后产生稳定最终排名且不能开始第九站。
- 保存损坏和重复赛后回调不能重复积分或污染其他模式数据。
- 自由赛事仍可自由选队/选图并使用随机牌组；教程仍满足既有隔离验收。
