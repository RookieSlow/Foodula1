# 《Foodula 1》音频风格与事件规范

> **状态**：In Progress — 设计已定义，项目内尚无音频资源或运行时音频系统。
> **创建日期**：2026-08-27。
> **资源清单**：`design/planning/asset-manifest.md` §5–§6。

---

## 一、音频目标

Foodula1 的音频应强化“桌游卡牌操作 + 轻松美食赛车”的节奏，而不是模拟写实赛车。声音首先服务规则可读性：玩家不看日志也应能听出选牌、换挡、支付/冷却热量、尾流、失控和完赛的差别。

三条原则：

1. **短促清楚**：大多数交互音效控制在 0.08–0.8 秒。
2. **克制而不空**：不使用爆炸、重撞击、刺耳警报或持续轰鸣掩盖 UI。
3. **玩法事件唯一映射**：支付热量与冷却、打出与弃牌、基础移动与尾流移动必须有不同声纹。

---

## 二、音乐方向

### 2.1 主菜单

- 轻松、带一点复古赛车节目感，可混合轻爵士鼓组、贝斯、木琴/拨弦和温和合成器。
- 速度约 90–115 BPM，不能显得紧张；科技树和车手选择共用时应适合长时间循环。
- 预留 0.5–1 秒淡入淡出，返回菜单时不突兀重启。

### 2.2 比赛

- 节奏明确但旋律不过度抢占注意力，建议 120–145 BPM。
- 以轻型电子鼓、弹性贝斯、短铜管/拨弦动机表达“美食赛车”而非军事或硬核竞速。
- 最后一圈优先使用同曲的增强层或短循环，避免切换到完全不同风格。
- 尾流特写只叠加短促音效，不改变整首音乐播放速度；慢放演出不得永久影响 AudioSource pitch。

### 2.3 结果

- 冠军与非冠军使用不同短提示，但都保持轻松、鼓励再次游玩。
- 结算面板停留期间可回到低音量菜单循环，不另做长结算曲也可接受。

## 三、音效语言

| 系统 | 主声纹 | 设计边界 |
|---|---|---|
| UI | 轻机械卡扣、木质/塑料桌游触感 | 不使用手机通知音式高频尖响 |
| 卡牌 | 纸张滑动、轻拍桌面 | 批量动画只播首张/尾张或做 80ms 限频 |
| 档位 | 小型机械拨杆、灶台旋钮 | 失败是“卡滞”，不是爆炸 |
| 热量 | 低频压力/温暖脉冲 | 支付偏暖；冷却偏清脆、带短空气感 |
| 赛车移动 | 轻悬架落点/棋子跳格 | 连续格数需合并，不能每格都过响 |
| 尾流 | 两段式：确认提示 + 气流推进 | 仅独立尾流阶段播放，不与速度牌基础移动混淆 |
| 弯道 | 成功、超速、失控三种不同结果 | 失控可用短胎鸣，不用碰撞爆炸 |
| 维修区 | 提示、进入、维护、驶出四阶段 | 维护音要与冷却热量相容但不相同 |
| 科技树 | 解锁上扬、激活确认、拒绝低沉 | 不能只靠音高区分，仍保留视觉状态 |

## 四、运行时混音与设置

- `Music`、`SFX`、`UI` 三组独立控制；主音量位于三者之上。
- 默认音乐低于规则音效约 5–8 dB；发生尾流、失控、完赛等关键事件时可短暂 duck 音乐 2–4 dB。
- 主菜单、比赛与结果切换使用 0.25–0.8 秒淡变，禁止突然截断循环尾部。
- 暂停或失焦时仅降低音乐，不应改变游戏规则计时；尾流 `Time.timeScale` 慢放不直接驱动音乐 pitch。
- 设置至少提供：主音量、音乐、音效、静音；数值保存可复用现有本地持久化方式。

## 五、实现与验收顺序

1. 建立 AudioMixer 与轻量音频服务，完成菜单/比赛音乐切换和三组音量设置。
2. 接入 P0 UI、卡牌、档位、热量、移动、尾流、弯道和完赛事件。
3. 在真实完整比赛日志对应的关键阶段逐项听验，确认事件不早播、不重复播、不跨回合残留。
4. 加入维修区、科技树、车手/赛道选择与天气环境声。
5. 在耳机与普通扬声器上验收，并检查长局中高频声音的疲劳度。

### Demo 验收标准

- 主菜单和比赛各有一条无缝循环音乐，场景切换无爆音。
- 支付热量、冷却热量、基础移动、尾流奖励移动能够仅凭声音区分。
- 批量抽牌/弃牌和长距离逐格移动不会形成噪声墙。
- 尾流慢放结束后音乐与音效速度、音高和音量全部恢复正常。
- 所有音频都能通过设置独立调节或静音；无缺失引用和 Console 错误。
